## Context

Today a project is implicitly always an audiobook: `electron/main/project.ts` reads/writes a JSON shape of `{ version, tracks, chapters, metadata }`, and `src/types.ts` / `electron/main/types.ts` have no notion of project "type". `BookMetadata` already has `series`/`seriesIndex` fields, but these describe a single book's position within a series conceptually — there is no structure representing the series itself as a saveable entity.

**RU:** Сейчас проект неявно всегда является аудиокнигой: `electron/main/project.ts` читает/записывает JSON-структуру `{ version, tracks, chapters, metadata }`, а `src/types.ts` / `electron/main/types.ts` не имеют понятия «типа» проекта. В `BookMetadata` уже есть поля `series`/`seriesIndex`, но они лишь концептуально описывают позицию одной книги в серии — структуры, представляющей саму серию как сохраняемую сущность, не существует.

## Goals / Non-Goals

**Goals:**
- Add a `type` discriminator to the project file format without breaking existing saved `.audiopie` files.
- Represent a `series` as its own lightweight project file that references audiobook files by path (not by embedding their full data), keeping series files small and avoiding data duplication/staleness.
- Let users bootstrap a new audiobook from a previous one's metadata to speed up multi-book workflows.

**RU (цели):** Добавить дискриминатор `type` в формат файла проекта, не ломая уже сохранённые `.audiopie`-файлы. Представить `series` как собственный лёгкий файл проекта, ссылающийся на файлы аудиокниг по пути (а не встраивая их данные целиком), сохраняя файлы серии небольшими и избегая дублирования/устаревания данных. Дать пользователям возможность начинать новую аудиокнигу на основе метаданных предыдущей, ускоряя работу над многокнижными сериями.

**Non-Goals:**
- Syncing/duplicating changes between a series and its member audiobooks' individual `series`/`seriesIndex` metadata fields automatically (e.g. auto-updating every member's `seriesIndex` when reordered in the series editor) — this is a reasonable follow-up but adds complexity (writing to N files) that's out of scope here.
- Moving/renaming referenced audiobook files from within the series editor (path management only; if a user moves a file on disk, it just shows as "missing" per the spec).
- A general-purpose "project template library" UI (this change only supports picking one existing file per new-project creation).

**RU (не цели):** Автоматическая синхронизация/дублирование изменений между серией и полями `series`/`seriesIndex` метаданных отдельных участников (например, автообновление `seriesIndex` у каждого участника при изменении порядка в редакторе серии) — разумное развитие в будущем, но добавляет сложность (запись в N файлов), выходящую за рамки этого изменения. Перемещение/переименование файлов аудиокниг из редактора серии (только управление путями; если пользователь переместит файл на диске, он просто отобразится как «отсутствует» согласно спецификации). Универсальный UI «библиотеки шаблонов проектов» (это изменение поддерживает выбор только одного существующего файла при создании нового проекта).

## Decisions

- **Reference by path, not by embedding.** A `series` project stores `audiobookPaths: string[]` rather than embedding each audiobook's metadata inline. This avoids the series file going stale when a member's metadata changes, at the cost of needing to resolve paths (and handle "missing" files) when rendering the series editor.
  - *Alternative considered*: embed a snapshot of each member's title/author/cover for a richer series list without reopening the files. Rejected for v1 to avoid a second synchronization problem; can revisit if performance of resolving N files becomes an issue.
  - **RU:** Ссылка по пути, а не встраивание. Проект `series` хранит `audiobookPaths: string[]`, а не встраивает метаданные каждой аудиокниги целиком. Это исключает устаревание файла серии при изменении метаданных участника, ценой необходимости разрешать пути (и обрабатывать «отсутствующие» файлы) при отрисовке редактора серии. *Рассмотренная альтернатива*: встраивать снимок названия/автора/обложки каждого участника ради более богатого списка серии без повторного открытия файлов. Отклонено для v1 во избежание второй проблемы синхронизации; можно пересмотреть, если разрешение путей для N файлов станет проблемой производительности.
- **Discriminated union at the type level.** `ProjectFile = AudiobookProjectFile | SeriesProjectFile`, discriminated by `type`. `electron/main/project.ts`'s open/save logic branches on `type`, defaulting absent `type` to `'audiobook'` at the point of reading (not by rewriting old files), preserving backward compatibility non-destructively.
  - **RU:** Дискриминированное объединение на уровне типов. `ProjectFile = AudiobookProjectFile | SeriesProjectFile`, различаемые по `type`. Логика открытия/сохранения в `electron/main/project.ts` ветвится по `type`, подставляя отсутствующий `type` как `'audiobook'` в момент чтения (без перезаписи старых файлов), что сохраняет обратную совместимость неразрушающим образом.
- **Template = metadata copy, not full clone.** "Create from existing project" (#27) intentionally only copies `BookMetadata` fields, not tracks/chapters/file path — reusing the existing `newProject()` reset-state path in `AppContext` and simply overlaying metadata afterward, rather than building a general "duplicate project file" feature.
  - *Alternative considered*: a literal file copy (duplicate `.audiopie` including tracks/chapters) followed by "Save As". Rejected because tracks reference absolute file paths that are almost always meant to change per book; copying them would likely confuse users into thinking old tracks were included.
  - **RU:** Шаблон = копия метаданных, а не полный клон. «Создать на основе существующего проекта» (#27) намеренно копирует только поля `BookMetadata`, не треки/главы/путь файла — переиспользуя существующий путь сброса состояния `newProject()` в `AppContext` и просто накладывая метаданные поверх, вместо реализации общей функции «дублировать файл проекта». *Рассмотренная альтернатива*: буквальное копирование файла (дублирование `.audiopie` вместе с треками/главами) с последующим «Сохранить как». Отклонено, поскольку треки ссылаются на абсолютные пути файлов, которые почти всегда должны меняться от книги к книге; их копирование, вероятно, запутает пользователей, заставив думать, что старые треки включены.

### UI navigation: unified series page, manual numbering, membership actions, create-new sub-screen

*(Captured 2026-09-06 from an explore session — visual/navigation decisions for how a series is browsed and edited.)*

*(Revised 2026-09-06, same day, after building and reviewing a first version: the standalone "series rail" column did not read well in practice and is dropped in favor of a single unified series management page. The rest of this subsection reflects the revised decisions; superseded rail-based decisions have been removed rather than kept as history, since the rail was never shipped to users.)*

- **A single unified series management page replaces the split `Books`/`Metadata` tabs and the navigation rail.** Instead of two `WorkspaceSidebar` sections (`Books`, `Metadata`) for a `series` project, there is one page — reusing `src/components/SeriesEditor.tsx` — laid out in two columns: **left**, the series' own metadata form (title, author, narrator, cover, description — the same fields as before, previously rendered by `MetadataForm` under the `Metadata` section); **right**, the ordered, drag-and-droppable list of member audiobooks (cover, title/author or "missing", editable series-position number — see below). `WorkspaceSidebar` for a `series` project now shows a single entry for this page plus `Settings`. There is no persistent navigation column to the left of `WorkspaceSidebar` for any project type.
  - *Why the rail was dropped*: a narrow, icon/avatar-heavy column duplicated information already visible once you're on the series page, and visually it read as clutter rather than navigation. The series' own page is now the single place to browse and manage members; opening a member still works the same way (click a row), it just doesn't get a permanently-visible sibling list once you're inside that member — see the "Back to series" action below for the return path.
  - **RU:** Единая страница управления серией заменяет раздельные вкладки `Books`/`Metadata` и панель навигации. Вместо двух разделов `WorkspaceSidebar` (`Books`, `Metadata`) для проекта `series` теперь одна страница — переиспользующая `src/components/SeriesEditor.tsx` — в двухколоночной раскладке: **слева** — собственная форма метаданных серии (название, автор, чтец, обложка, описание — те же поля, что и раньше, прежде отображавшиеся `MetadataForm` в разделе `Metadata`); **справа** — упорядоченный, поддерживающий drag-and-drop список входящих аудиокниг (обложка, название/автор либо «отсутствует», редактируемый номер позиции в серии — см. ниже). `WorkspaceSidebar` для проекта `series` теперь показывает один пункт для этой страницы плюс `Settings`. Постоянной колонки навигации слева от `WorkspaceSidebar` больше нет ни для одного типа проекта. *Почему панель убрали*: узкая колонка из иконок/аватаров дублировала информацию, уже видимую на самой странице серии, и визуально воспринималась как загромождение, а не навигация. Собственная страница серии теперь единственное место для просмотра и управления участниками; открытие участника работает так же (клик по строке), просто постоянно видимого списка соседей внутри открытого участника больше нет — см. действие «К серии» ниже для пути назад.

- **Series-position numbers are manual and live on the member's own file, not the series file.** Each row in the right column shows an editable number, read from and written back to that member audiobook's own `metadata.seriesIndex` field (which already existed in `BookMetadata` but was previously unused for this purpose) via a new IPC (`project.updateMemberSeriesIndex(memberPath, seriesIndex)`) that opens, patches, and re-saves just that one file. This is deliberately decoupled from the row's position in the drag-ordered list: dragging changes `audiobookPaths` order (and therefore default display order), while the number is a free-form label a user sets independently — e.g. a series file containing only two audiobooks can still show them as "15" and "16" if that's their place in a longer real-world series the user only partially catalogued.
  - *Alternative considered*: store `number` alongside each path in the series file itself (`audiobookPaths: string[]` → `members: { path: string; number?: number }[]`). Rejected: it would duplicate data that conceptually belongs to the book (its own `seriesIndex`), require a series-file schema migration, and risk drifting from the book's own metadata if ever both were edited independently.
  - **RU:** Номера позиций в серии — ручные и живут в собственном файле участника, а не в файле серии. Каждая строка в правой колонке показывает редактируемый номер, который читается из и записывается обратно в собственное поле `metadata.seriesIndex` этой аудиокниги (поле уже существовало в `BookMetadata`, но раньше не использовалось для этой цели) через новый IPC (`project.updateMemberSeriesIndex(memberPath, seriesIndex)`), который открывает, патчит и пересохраняет именно этот один файл. Это намеренно отделено от позиции строки в списке, определяемой drag-and-drop: перетаскивание меняет порядок `audiobookPaths` (и, соответственно, порядок отображения по умолчанию), а номер — это произвольная метка, которую пользователь задаёт независимо — например, файл серии, содержащий всего две аудиокниги, всё равно может показывать их как «15» и «16», если это их место в более длинной реальной серии, которую пользователь каталогизировал лишь частично. *Рассмотренная альтернатива*: хранить `number` рядом с каждым путём в самом файле серии (`audiobookPaths: string[]` → `members: { path: string; number?: number }[]`). Отклонено: это дублировало бы данные, концептуально принадлежащие книге (её собственный `seriesIndex`), требовало бы миграции схемы файла серии и рисковало бы рассинхронизацией, если оба места редактировались бы по отдельности.

- **Drag-and-drop on the series page's member list is always-on, like `ChapterList`, not an explicit toggle mode.** Because the member list is now a full column on a dedicated page (not a narrow persistent rail shared with click-to-navigate elsewhere), the earlier "explicit reorder mode" concern (accidental drags competing with single-click navigation in a cramped rail) no longer applies. The list follows the same always-visible-grip-handle pattern as `ChapterList` (`sortablejs` with a `.drag-handle` grip on each row); clicking the row body (not the handle) still opens that member.
  - **RU:** Drag-and-drop в списке участников на странице серии всегда активен, как в `ChapterList`, а не через явный режим-переключатель. Поскольку список участников теперь полноценная колонка на отдельной странице (а не узкая постоянная панель, где нужно и кликать для навигации, и тащить), прежнее опасение про «явный режим изменения порядка» (случайные перетаскивания конкурируют с кликом-навигацией в узкой панели) больше не актуально. Список следует тому же паттерну постоянно видимого хендла, что и `ChapterList` (`sortablejs` с хендлом `.drag-handle` на каждой строке); клик по телу строки (не по хендлу) всё так же открывает этого участника.

- **Adding a member is a floating "Add book" button, page-scoped, opening a two-option menu.** The series page's own "+"/add action moves from a header button into the same floating-action-button slot `App.tsx` uses for "Build" on an `audiobook` project — a FAB pinned to the bottom of the main content area — but shown only while the series page is the active view (an `audiobook` project's FAB stack is unchanged: Save + Build). Clicking it opens a small menu with two entries: "Attach existing audiobook" (the pre-existing file-picker flow, unchanged) and "Create new audiobook in this series" (new, see below).
  - **RU:** Добавление участника — плавающая кнопка «Добавить книгу», привязанная к странице, открывающая меню с двумя пунктами. Собственное действие «+»/добавить на странице серии переезжает из кнопки в шапке в тот же слот плавающей кнопки, который `App.tsx` использует для «Собрать» в проекте `audiobook` — кнопка закреплена внизу основной области контента — но отображается только когда активна страница серии (стек плавающих кнопок проекта `audiobook` не меняется: Сохранить + Собрать). Клик открывает небольшое меню с двумя пунктами: «Прикрепить существующую аудиокнигу» (уже существующий сценарий выбора файла, без изменений) и «Создать новую аудиокнигу в этой серии» (новое, см. ниже).

- **Creating a new book "in" a series pre-fills shared metadata and self-registers on first save, rather than being added to the series list up front.** Choosing "Create new audiobook in this series" calls the existing `newProject('audiobook', metadataOverlay)` path in `AppContext` with `metadataOverlay` seeded from the series' own `author`/`narrator`/`coverPath`, and sets `activeSeriesContext` to `{ seriesPath: <current series path>, audiobookPaths: <current members> }` — the new book is *not* appended to `audiobookPaths` yet, since it has no file path until saved. The user then edits it as a normal `audiobook` project (tracks, chapters, its own metadata, including its own `seriesIndex`). The first time `handleSaveProject` (in `App.tsx`) succeeds for a book with an `activeSeriesContext` whose `audiobookPaths` does not yet include the saved path, it also appends that path to the series and persists the series file — reusing the same path-only "add member" IPC as the "attach existing" flow. This resolves the previously open question ("shortcut to create a new audiobook directly as the next book in this series").
  - *Alternative considered*: require the series file to be re-saved with a placeholder/pending path immediately, before the user starts editing the new book. Rejected: a series file should only ever reference books that actually exist on disk (consistent with the existing "reference by path, not embedding" decision) — an unsaved book has no path to reference yet.
  - **RU:** Создание новой книги «в» серии предзаполняет общие метаданные и самостоятельно регистрируется при первом сохранении, а не добавляется в список серии заранее. Выбор «Создать новую аудиокнигу в этой серии» вызывает существующий метод `newProject('audiobook', metadataOverlay)` в `AppContext` с `metadataOverlay`, заполненным из собственных `author`/`narrator`/`coverPath` серии, и устанавливает `activeSeriesContext` в `{ seriesPath: <путь текущей серии>, audiobookPaths: <текущие участники> }` — новая книга *ещё не* добавляется в `audiobookPaths`, поскольку у неё нет пути файла до сохранения. Затем пользователь редактирует её как обычный проект `audiobook` (треки, главы, собственные метаданные, включая собственный `seriesIndex`). При первом успешном срабатывании `handleSaveProject` (в `App.tsx`) для книги с `activeSeriesContext`, чей `audiobookPaths` ещё не включает сохранённый путь, система также добавляет этот путь в серию и сохраняет файл серии — переиспользуя тот же IPC добавления участника только по пути, что и сценарий «прикрепить существующую». Это закрывает ранее открытый вопрос («быстрый способ создать новую аудиокнигу сразу как следующую книгу в этой серии»). *Рассмотренная альтернатива*: требовать немедленного пересохранения файла серии с временным/отложенным путём ещё до того, как пользователь начнёт редактировать новую книгу. Отклонено: файл серии должен ссылаться только на книги, реально существующие на диске (согласуется с существующим решением «ссылка по пути, а не встраивание») — у несохранённой книги пути для ссылки пока нет.

- **Series membership actions surface in `MetadataForm`, driven by session context, not by a metadata field.** When the open `audiobook` was launched via `project.openSeriesMember()` *or* created via "Create new audiobook in this series", `MetadataForm` shows a small "Part of series: `<title>`" callout with two buttons: "Remove from series" and "Back to series", sourced from `activeSeriesContext` — not from the book's own free-text `metadata.series` field, which remains independent and unrelated to structural membership (per the existing Open Question below). "Remove from series" calls the existing path-only IPC that removes this book's path from the series file's `audiobookPaths` without touching the book's own `.audiopie` file. "Back to series" opens the series project at `activeSeriesContext.seriesPath` (prompting a save first if the current book has unsaved changes), returning to the unified series page. The book's title and `seriesIndex` stay editable via their own fields in this same form as well as from the series page's member list (both write to the same file, so either place reflects the other next time it's read).
  - **RU:** Действия по принадлежности к серии отображаются в `MetadataForm`, управляются контекстом сессии, а не полем метаданных. Когда открытая `audiobook` была запущена через `project.openSeriesMember()` *или* создана через «Создать новую аудиокнигу в этой серии», `MetadataForm` показывает небольшой блок «Входит в серию: `<название>`» с двумя кнопками: «Убрать из серии» и «К серии», данные берутся из `activeSeriesContext`, а не из собственного текстового поля `metadata.series` книги, которое остаётся независимым и не связано со структурной принадлежностью (см. открытый вопрос ниже). «Убрать из серии» вызывает существующий IPC, работающий только с путём, который удаляет путь этой книги из `audiobookPaths` файла серии, не трогая сам файл книги. «К серии» открывает проект серии по пути `activeSeriesContext.seriesPath` (предварительно предлагая сохранить, если в текущей книге есть несохранённые изменения), возвращая на единую страницу серии. Название книги и `seriesIndex` остаются редактируемыми через собственные поля в этой же форме, а также из списка участников на странице серии (оба места пишут в один и тот же файл, поэтому изменения в одном отражаются в другом при следующем чтении).

- **"Create new" becomes a sub-screen, not additional top-level cards.** `ProjectManager` keeps its existing two top-level cards ("Open Project" / "Create New"). Clicking "Create New" opens a sub-screen/dialog offering two tiles in the same visual language as the existing cards — "Audiobook" and "Series". Choosing "Audiobook" reveals the existing-template choice from #27 as a secondary option within the same sub-screen ("Start blank" vs. "Start from existing project…" file picker). Choosing "Series" creates a blank `series` project directly (its own metadata is filled in afterward via the left column of its own unified series page).
  - **RU:** «Создать новый» становится подэкраном, а не новыми карточками верхнего уровня. `ProjectManager` сохраняет два существующих верхнеуровневых карточки («Открыть проект» / «Создать новый»). Клик по «Создать новый» открывает подэкран/диалог с двумя плитками в том же визуальном стиле, что и существующие карточки — «Аудиокнига» и «Серия». Выбор «Аудиокнига» показывает существующий выбор шаблона из #27 как вторичную опцию в том же подэкране («Начать с пустого» vs. «Начать на основе существующего проекта…» с выбором файла). Выбор «Серия» создаёт пустой проект `series` напрямую (его собственные метаданные заполняются позже через левую колонку его собственной единой страницы серии).

- **Implementation defaults for the series page (resolved now to keep this actionable, not left open):**
  - *Back navigation*: "Back to series" in `MetadataForm`'s "Part of series" callout is the only way back to the series-level view from an open member; the `WorkspaceSidebar` footer's "Close" item keeps its current meaning (closes the whole open project) regardless of whether the book was reached directly or via a series — no special-casing of "Close" needed.
  - *Row numbering*: each row in the right column shows both the editable manual number (bound to `metadata.seriesIndex`, may be blank) and, distinctly, a small muted drag-order index — so a user can tell "this is the 2nd item in my list" apart from "this book's number is 15" at a glance.
  - *No rail, no `sidebarMode` branching*: since there is no separate rail, the series page's column widths and row density are fixed by its own layout, not by the `sidebarMode` (`expanded`/`minimal`) setting used elsewhere for `WorkspaceSidebar`.
  - **RU:** Дефолты реализации для страницы серии (закрыты сейчас, чтобы не оставлять зависшими): *Навигация назад* — «К серии» в блоке «Входит в серию» на `MetadataForm` — единственный способ вернуться к виду серии из открытого участника; пункт «Закрыть» в подвале `WorkspaceSidebar` сохраняет текущий смысл (закрывает весь открытый проект) независимо от того, как была открыта книга — особый случай не нужен. *Нумерация строк* — каждая строка в правой колонке показывает и редактируемый ручной номер (привязан к `metadata.seriesIndex`, может быть пустым), и отдельно приглушённый индекс порядка перетаскивания — чтобы пользователь мог на глаз отличить «это второй элемент в моём списке» от «номер этой книги — 15». *Без панели, без ветвления по `sidebarMode`* — поскольку отдельной панели больше нет, ширины колонок и плотность строк страницы серии определяются её собственной раскладкой, а не настройкой `sidebarMode` (`expanded`/`minimal`), используемой в остальных местах для `WorkspaceSidebar`.

## Risks / Trade-offs

- [Risk] Series files reference audiobooks by absolute path, which breaks if a user moves the project folder or shares it with another machine → Mitigation: covered by the "missing member" scenario in the spec (graceful degradation, not a hard failure); a future change could add path re-linking.
  - **RU:** [Риск] Файлы серий ссылаются на аудиокниги по абсолютному пути, что ломается при перемещении папки проекта или переносе на другую машину → Смягчение: покрыто сценарием «отсутствующий участник» в спецификации (плавная деградация, а не жёсткий сбой); в будущем изменении можно добавить повторное связывание путей.
- [Risk] `ProjectManager.tsx`'s "Open Project" flow currently assumes an opened file completes the UI-completeness check (non-empty tracks/chapters/title) per the existing `project-persistence` spec — that check is `audiobook`-specific and must be branched so opening a `series` file (which has no tracks/chapters) doesn't get incorrectly rejected → Mitigation: explicitly special-case `type: 'series'` in the open-completeness check.
  - **RU:** [Риск] Сценарий «Открыть проект» в `ProjectManager.tsx` сейчас предполагает, что открытый файл проходит проверку полноты UI (непустые треки/главы/название) согласно текущей спецификации `project-persistence` — эта проверка специфична для `audiobook` и должна быть разветвлена, чтобы открытие файла `series` (без треков/глав) не отклонялось некорректно → Смягчение: явно выделить особый случай `type: 'series'` в проверке полноты при открытии.
- [Trade-off] The manual `seriesIndex` number and the drag-ordered list position are two independent sources of "order" that can disagree (e.g. the list shows book "16" above book "15" because that's how they were dragged) → acceptable and intentional per the "manual numbering" decision above: the drag order controls default display/list position, the number is purely a user-facing label, and no code path assumes they match.
  - **RU:** [Компромисс] Ручной номер `seriesIndex` и позиция в списке, заданная перетаскиванием, — два независимых источника «порядка», которые могут не совпадать (например, список показывает книгу «16» выше книги «15», потому что так их перетащили) → приемлемо и осознанно согласно решению «ручная нумерация» выше: порядок перетаскивания определяет позицию отображения/списка по умолчанию, номер — чисто пользовательская метка, и никакой код не предполагает их совпадения.
