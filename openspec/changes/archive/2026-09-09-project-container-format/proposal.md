## Why

`.audiopie` is currently a plain JSON file that only ever references source MP3s by their absolute path on disk (`tracks[].path`). This creates two compounding problems: (1) a project breaks the moment a referenced MP3 moves, is renamed, or the project file is shared with someone else / another machine, and (2) the in-progress `project-types-and-series` change tried to model a multi-book series as a *second* project file that itself only stores paths to other `.audiopie` files — doubling down on the same fragile "pile of files held together by absolute paths" approach instead of fixing it. Both single audiobooks and series need one self-contained, portable project file that actually owns its audio data, the way a `.docx` or `.psd` owns its embedded media instead of pointing at loose files on disk.

**RU:** Сейчас `.audiopie` — обычный JSON-файл, который лишь хранит абсолютные пути к исходным MP3 (`tracks[].path`). Это создаёт две накапливающиеся проблемы: (1) проект ломается, как только исходный MP3 перемещён, переименован или сам файл проекта передан другому человеку/на другой компьютер, и (2) незавершённый change `project-types-and-series` пытался представить серию как *второй* файл проекта, который сам хранит лишь пути к другим `.audiopie`-файлам — усугубляя тот же хрупкий подход «кучка файлов, связанных абсолютными путями», вместо того чтобы его исправить. И отдельной аудиокниге, и серии нужен один самодостаточный, переносимый файл проекта, который реально владеет своими аудиоданными — как `.docx` или `.psd` владеют встроенными медиа, а не ссылаются на файлы где-то на диске.

## What Changes

- **BREAKING** (file format): `.audiopie` becomes a ZIP container (stored, not deflated — MP3 is already compressed) instead of a bare JSON file. Layout: a tiny root `index.json` (`{ version, type, series?, bookOrder }`) plus a `books/<bookId>/` directory per book, and each book directory owns its *own* `index.json` (metadata + tracks), its chapter MP3s as sequentially numbered files (`1.mp3`, `2.mp3`, ...), and its own optional cover image. There is no shared top-level `covers/` directory and no series-level cover — a series represents itself visually via its books' own covers.
- Adding a track now **copies** the source MP3 into the project's working directory immediately (not just recording its external path). Opening a project extracts the ZIP into a per-session working directory; saving re-zips that working directory back to the `.audiopie` path. This mirrors how Office/PSD-style container formats behave (edit an extracted working copy, repackage on save), and is why we picked this over embedding structure inside a single JSON (binary-safe, still just a ZIP any tool can inspect).
- Introduce a `type` field: `audiobook` (exactly one book in `bookOrder`) or `series` (one or more, plus shared `series` metadata: title, author, narrator, description). Because a book folder's on-disk shape is identical either way, `type` is **mutable after creation**, from a "danger zone" section in the project's Settings — not just chosen once up front. Switching `audiobook → series` is free; switching `series → audiobook` permanently deletes every book except the first (by list order) and requires an explicit confirmation modal warning about the deletion. This **replaces** the `project-types-and-series` change's design of "a series is a separate file that stores paths to other project files" — a series is now just a project with more than one book folder inside the same container. That in-progress change is superseded by this one; its still-relevant UI ideas (unified series management page, manual per-book series numbering, "add book" FAB menu, "part of series" callout) are carried forward here, retargeted at the new single-container model.
- "Create new project" now always asks the user to pick a save location for the container **before** editing begins (rather than editing an unsaved in-memory project and only being asked to choose a path on first Save) — creating a book or a series both start by creating the `.audiopie` file up front, then opening it for editing.
- Legacy plain-JSON `.audiopie` files continue to open exactly as today (tracks still point at their original external paths). The first time such a project is saved, it is transparently upgraded: referenced MP3s are copied into a new ZIP container at the same path, converting it in place to the new format. **Not breaking** for existing saved projects — no user action is required to keep opening old files, only saving upgrades them.
- Adding/removing/reordering chapters, and the "1 track = 1 chapter" auto-numbering behavior, are unchanged — only where the underlying MP3 bytes live changes.

**RU:** **BREAKING** (формат файла): `.audiopie` становится ZIP-контейнером (без сжатия — MP3 уже сжат) вместо обычного JSON. Структура: крошечный корневой `index.json` (`{ version, type, series?, bookOrder }`) плюс директория `books/<bookId>/` на каждую книгу, и каждая директория книги владеет собственным `index.json` (метаданные + треки), главами-MP3 и собственной опциональной обложкой. Общей директории `covers/` и обложки уровня серии нет — серия представляет себя визуально через обложки своих книг. Добавление трека теперь сразу **копирует** исходный MP3 в рабочую директорию проекта. Открытие распаковывает ZIP во временную рабочую директорию сессии; сохранение — упаковывает её обратно. Введено поле `type`: `audiobook` (ровно одна книга в `bookOrder`) или `series` (одна и более, плюс общие метаданные серии). Поскольку структура папки книги на диске одинакова для обоих типов, `type` можно **менять и после создания** — из «опасной зоны» настроек проекта. Переключение `audiobook → series` — бесплатное; `series → audiobook` безвозвратно удаляет все книги кроме первой и требует явного подтверждения. Это заменяет подход change `project-types-and-series`; этот change считается заменённым (superseded), а его полезные UI-идеи переносятся сюда. «Создать новый проект» теперь сразу просит выбрать путь сохранения контейнера, до начала редактирования. Старые plain-JSON `.audiopie` продолжают открываться как раньше и незаметно обновляются до нового формата при первом сохранении — не является ломающим изменением для уже сохранённых проектов.

## Capabilities

### New Capabilities
- `project-container-format`: The ZIP-based `.audiopie` container itself — the split root/per-book `index.json` schema, `books/<bookId>/` layout (each self-contained, no shared `covers/`), the open-extracts/save-repacks working-directory lifecycle, and transparent upgrade of legacy plain-JSON files on first save.
- `project-types`: The `audiobook`/`series` distinction living inside one container, "create new" requiring an up-front save location, the series management UI (unified series page, per-book manual series numbering, attach/create book actions, "part of series" callout on a member book), and a post-creation Settings "danger zone" to switch a project's type.

### Modified Capabilities
- `project-persistence`: Replace the "JSON file" requirements with "ZIP container" requirements (format, save/open flows, empty-project guard, legacy migration on save). Superseded by the new container semantics rather than incrementally amended.
- `track-management`: "Add tracks" now copies the source file into the project's working directory instead of only recording its external path; removing a track also removes its copied file from the working directory.

## Impact

- `electron/main/project.ts`: rewritten around a working-directory model — `openProjectFromFile` extracts a ZIP to a temp dir (or reads/upgrades a legacy JSON in place), `saveProjectToFile` re-zips the working directory; reads/writes the root `index.json` plus each book's own `books/<bookId>/index.json` instead of one flat JSON structure.
- `electron/main/projectFile.ts` (new): ZIP packing/unpacking helpers (`zip`/`unzip` via a library such as `yazl`/`yauzl` or `adm-zip`), working-directory path helpers, legacy-format detection (`PK\x03\x04` signature vs. JSON).
- `electron/main/ipc.ts` / `electron/preload/preload.ts`: `tracks.addFromPaths` copies files into the working dir's `books/<bookId>/` and returns container-relative paths; new `project.new(type, savePath)` requiring a path up front; new `project.setType(type)` for the Settings danger zone; series member management handlers operate on `bookOrder` plus per-book `index.json` files instead of separate project files.
- `src/types.ts` / `electron/main/types.ts`: `TrackInfo.path` becomes container-relative; new `ProjectType`, `SeriesMetadata` (no cover field), `BookEntry` types; root `index.json`'s shape (`version`, `type`, `series?`, `bookOrder`) replaces the flat `{ tracks, chapters, metadata }` shape, with per-book metadata/tracks moved into each book's own `index.json`.
- `src/components/ProjectManager.tsx`: "Create new" flow now shows a save-location dialog before entering the editor, for both audiobook and series.
- Settings UI: new "Danger zone" section to switch `type`, including the deletion-confirmation modal for `series → audiobook`.
- Build (`electron/main/ffmpeg.ts`): reads chapter MP3s from the extracted working directory (path unchanged from FFmpeg's perspective — it already needs real files on disk).
- New dependency: a ZIP library for Node/Electron (evaluated in design.md).
- `openspec/changes/project-types-and-series/`: marked superseded by this change; not archived as completed, its groundwork is carried forward here instead.
